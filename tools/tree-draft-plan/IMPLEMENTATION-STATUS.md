# Tree-Draft implementation status

This file tracks implementation acceptance separately from the architecture manifests and DAG.
The 400 manifest files remain the source of truth for dependency structure. A module is marked
accepted here only after static review, focused tests, relevant build validation, and dependency
compatibility review.

## States

- `planned`: manifest exists but implementation has not been dispatched.
- `dispatched`: exactly one worker owns this manifest for the current implementation attempt.
- `review`: implementation returned and is under prime review.
- `accepted`: implementation passed the required review and validation gates.
- `blocked`: a material blocker prevents acceptance; the blocker must be recorded explicitly.

## Acceptance gate

For every module, record acceptance only after all applicable checks pass:

1. Static review against the exact current manifest.
2. Compatibility with existing llama.cpp C++/CUDA/Triton/runtime interfaces.
3. Focused tests for the module contract.
4. Relevant build target validation.
5. DAG dependency revalidation before releasing successors.
